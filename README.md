# LifeOS

Личная система управления жизнью. Первый модуль — **LifeOS RPG**: XP за реальные
действия, уровни, характеристики, квесты.

## Статус

| Часть | Состояние |
|---|---|
| Фаза 1 — ядро: профиль, XP Ledger, уровни | готово |
| Фаза 2 — квесты: daily / weekly / personal / challenge / milestone | готово |
| Авторизация: JWT + refresh-токены с ротацией, Argon2id | готово |
| Клиент (PWA: React + TypeScript + Vite): главная, квесты, профиль | готово |
| Фаза 3 — привычки, серии с заморозками, 20 достижений | готово |
| Фаза 4 — циклы: цели, пауза, итоговый отчёт и награда | готово |
| Фаза 5 — Adaptive Engine: анализ активности, советы с подтверждением | готово |
| Фаза 6 — аналитика и полировка | дальше |

Принятые решения по ТЗ и отклонения от него — в [docs/decisions.md](docs/decisions.md).

## Структура

```
backend/
  app/domain/      правила игры без БД: уровни, награды, локальные даты
  app/services/    сценарии: XP Ledger, квесты, привычки, достижения, циклы, советы, профиль
  app/routers/     HTTP API /api/v1
  migrations/      миграции Alembic
  tests/           тесты на настоящем PostgreSQL
web/
  src/api/         клиент API: токены, повторы, Idempotency-Key, типы из OpenAPI
  src/pages/       экраны: главная, квесты, привычки, циклы, анализ и советы, достижения, профиль
  src/components/  интерфейс Premium Dark
  src/i18n/        тексты RU и EN
scripts/           devdb.ps1 (PostgreSQL), dev.ps1, prod.ps1, backup.ps1, autostart.ps1
docs/              решения и документация
```

## Запуск на Windows

Нужны Python 3.14, Node.js 22+, PostgreSQL 18 (достаточно программ, служба не нужна) и Git.

Если программы ставились, пока терминал (или приложение, в котором он открыт) уже
работал, сначала перезапусти его. Иначе терминал не увидит новые программы, и
появится ошибка вроде `Имя "npm.cmd" не распознано`. Скрипт `dev.ps1` сам
перечитывает `PATH`, поэтому работает и без перезапуска.

Все команды ниже выполняются из папки проекта (`LifeOS`) в Windows PowerShell.

### Один раз: база и зависимости

```powershell
# База данных: кластер, роль lifeos, базы lifeos, lifeos_dev и lifeos_test, пароли в backend\.env
powershell -ExecutionPolicy Bypass -File .\scripts\devdb.ps1 init

# Зависимости бэкенда
cd backend
py -3.14 -m venv .venv
.\.venv\Scripts\python -m pip install -e ".[dev]"
cd ..
```

### Каждый раз: запуск

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\dev.ps1
```

Скрипт выполняет такие шаги:
1. Запускает PostgreSQL. После перезагрузки компьютера он остановлен, поэтому этот шаг нужен.
2. Применяет миграции.
3. При первом запуске ставит зависимости клиента.
4. Открывает два окна: «LifeOS API» (http://127.0.0.1:8000/docs) и «LifeOS Web».

Режим разработки работает со своей базой `lifeos_dev` (адрес — `DEV_DATABASE_URL`
в `backend\.env`): эксперименты и недописанные миграции не трогают настоящие данные
в `lifeos`, с которой работает рабочий режим.

Приложение открывается на **http://localhost:5173**. Чтобы остановить сервер,
закрой его окно или запусти `dev.ps1 -Stop`; `dev.ps1 -Restart` перезапускает оба
сервера. Базу останавливает команда `.\scripts\devdb.ps1 stop`, а
`.\scripts\devdb.ps1 status` показывает, запущена ли она.

**С телефона.** Запусти `dev.ps1 -Lan`: скрипт напечатает адрес вида
`http://192.168.x.x:5173`, открой его на телефоне в той же сети Wi-Fi. Если Windows
считает эту сеть общедоступной, брандмауэр не пустит телефон (скрипт об этом
предупредит). Переключи сеть на частную: Параметры → Сеть и Интернет → Wi-Fi →
свойства сети → Тип сетевого профиля → «Частная сеть». Когда Windows спросит про
Node.js, разреши доступ.
Так приложение работает как сайт. Чтобы установить его на главный экран и получать
уведомления, нужен HTTPS: это даст Tailscale или сервер на этапе деплоя.

### Каждый день: рабочий режим и доступ с телефона через Tailscale (HTTPS)

Рабочий режим — это один фоновый процесс, который отдаёт и API, и собранное
приложение на `http://127.0.0.1:8080`. Извне этот адрес недоступен. Tailscale
публикует его по HTTPS только для твоих устройств, в открытом интернете
приложения нет. Компьютер при этом должен быть включён.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\prod.ps1          # запуск (-Status, -Stop, -Build)
powershell -ExecutionPolicy Bypass -File .\scripts\autostart.ps1     # запускать при входе в Windows
powershell -ExecutionPolicy Bypass -File .\scripts\backup.ps1        # резервная копия вручную
```

`prod.ps1` по порядку:
1. Запускает PostgreSQL.
2. Делает резервную копию базы, но не чаще раза в сутки. Копии лежат в
   `Документы\LifeOS-backups`, хранятся последние 14.
3. Применяет миграции.
4. Пересобирает клиент, если менялись его исходники. Сборка лежит в `web\dist-prod`,
   её пишет только `prod.ps1`; `npm run build` при разработке пишет в `web\dist` и
   работающее приложение не меняет.
5. Поднимает сервер.

Рабочий режим может работать одновременно с режимом разработки (`dev.ps1`, порты
8000 и 5173). Логи пишутся в `%LOCALAPPDATA%\LifeOS\api.log`.

**Обновление** после `git pull` или слияния веток:
`prod.ps1 -Stop`, затем `prod.ps1`. Скрипт сделает резервную копию (если сегодня её
ещё не было), применит миграции, пересоберёт клиент и запустит новую версию.

Настройка Tailscale, один раз:
1. Установи Tailscale на компьютер (`winget install --id Tailscale.Tailscale -e`) и
   войди в аккаунт: подойдёт Google, Microsoft, GitHub или Apple.
2. В консоли https://login.tailscale.com/admin/dns включи **MagicDNS** и
   **HTTPS Certificates**. Здесь же можно переименовать компьютер, например в
   `lifeos`, — так адрес будет короче.
3. Опубликуй рабочий режим внутри своей сети Tailscale:
   `& "C:\Program Files\Tailscale\tailscale.exe" serve --bg 8080`.
   Команда напечатает адрес вида `https://<компьютер>.<сеть>.ts.net`.
4. На телефон поставь приложение Tailscale и войди в тот же аккаунт. Открой этот
   адрес и установи приложение: в Safari — «Поделиться» → «На экран „Домой“», в
   Chrome — «Установить приложение».

### Тесты и сборка

```powershell
cd backend; .\.venv\Scripts\python -m pytest; cd ..   # бэкенд, база lifeos_test пересоздаётся
cd web; npm.cmd test; npm.cmd run build; cd ..        # клиент: тесты, типы, сборка PWA
```

`npm.cmd` вместо `npm`: в Windows PowerShell по умолчанию запрещён запуск скриптов,
и обычный `npm` (это `npm.ps1`) выдаёт ошибку.

**Типы API.** После изменения бэкенда обнови типы клиента:
`backend\.venv\Scripts\python backend\scripts\export_openapi.py`, затем `npm.cmd run api:types` в `web`.

`devdb.ps1 init` создаёт кластер в `%LOCALAPPDATA%\LifeOS\pgdata`, роль `lifeos`
и базы `lifeos`, `lifeos_dev` и `lifeos_test`. Случайные пароли он записывает в `backend/.env`,
файл в git не попадает. Служба Windows и права администратора не нужны. Запускай
его в обычном терминале: в изолированной среде (например, у AI-агента) кластер
окажется виден только этой среде.

Почему не используется служба из установщика: штатный установщик PostgreSQL
запускает `initdb` с системной локалью `Russian_Russia.1251`. В итоге он падает с
ошибкой `invalid byte sequence for encoding "UTF8"`, и кластер не создаётся.
`devdb.ps1` создаёт кластер с локалью `C` и встроенным провайдером сортировки
`C.UTF-8`, такой кластер не зависит от языка Windows.

## API

Все пути начинаются с `/api/v1`, полная схема — в `/docs`.

| Метод и путь | Что делает |
|---|---|
| `POST /auth/register`, `/auth/login` | регистрация и вход, ответ — пара токенов |
| `POST /auth/refresh`, `/auth/logout` | ротация и отзыв refresh-токена |
| `POST /account/delete` | удаление аккаунта со всеми данными |
| `GET/PATCH /player/profile` | профиль, уровень, прогресс, часовой пояс |
| `GET /player/attributes` | характеристики с динамикой за 7 и 30 дней |
| `GET /player/xp-history` | журнал XP, новые записи сверху |
| `GET /player/statistics` | XP по дням и характеристикам за период |
| `GET/POST /quests`, `GET/PATCH/DELETE /quests/{id}` | квесты (`?scope=today` — квесты на сегодня) |
| `POST /quests/{id}/complete`, `/skip`, `/undo` | выполнить, пропустить, отменить до конца дня |
| `GET/POST /habits`, `GET/PATCH/DELETE /habits/{id}` | привычки (DELETE переносит в архив) |
| `POST /habits/{id}/complete`, `/undo`, `/freeze` | отметить сегодня, отменить, заморозить пропуск |
| `GET /habits/{id}/streak` | текущая и лучшая серия |
| `GET /achievements`, `/achievements/unlocked` | каталог с прогрессом и полученные достижения |
| `GET/POST /cycles`, `GET /cycles/current` | история циклов, новый цикл с целями, текущий цикл |
| `GET/PATCH/DELETE /cycles/{id}` | цикл с прогрессом или отчётом; DELETE отменяет цикл |
| `POST /cycles/{id}/pause`, `/resume`, `/complete` | пауза, продолжение, подвести итоги |
| `POST /cycles/{id}/goals`, `PATCH/DELETE /cycles/{id}/goals/{goal_id}` | цели цикла |
| `GET /adaptive/summary` | план и сделанное за 7 и 30 дней, что чаще срывается |
| `GET /adaptive/recommendations` | советы: запрос обновляет их, но план не меняет |
| `POST /adaptive/recommendations/{id}/apply`, `/dismiss` | применить выбранные изменения или отказаться |
| `GET /config/levels`, `/config/rewards` | таблица уровней и награды с сервера |

POST-запросы принимают заголовок `Idempotency-Key`. Повтор с тем же ключом
возвращает первый ответ и не выполняет действие заново.

## Как начисляется XP

- Награду всегда считает сервер: она зависит от типа, активности и сложности
  квеста и фиксируется при создании квеста.
- Каждое начисление — запись в неизменяемом журнале `xp_ledger`. Ключ записи
  детерминированный, поэтому одно событие не может дать XP дважды.
- Профиль и характеристики обновляются в той же транзакции. Строка профиля
  блокируется, поэтому параллельные запросы не теряют XP.
- Пропуск квеста XP не снимает. Отмена ошибочного выполнения добавляет
  компенсирующую запись в журнал и доступна до конца того же дня.
