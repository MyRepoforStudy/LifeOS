# Решения по ТЗ LifeOS RPG

Решения приняты при разборе ТЗ версии 1.0 (19.11.2026). Номера соответствуют
списку вопросов.

## Продукт и стек

1. **LifeOS как основа.** Пока это самостоятельное приложение со своими пользователями.
   Задача — это Personal Quest со сложностью. Модули Tasks, Learning, Health и Finance
   появятся позже и будут присылать события в RPG.
2. **Для кого.** Только для себя, но данные пользователей изолированы. Вход по email
   и паролю. Сброс пароля по почте и вход через Google/Apple отложены.
3. **Клиент.** PWA на React + TypeScript + Vite. На iPhone ставится через Safari →
   «На экран „Домой“», на Android — через Chrome. Магазины приложений и платные
   аккаунты разработчика не нужны. Позже код можно обернуть в Capacitor.
4. **Первая итерация.** Фазы 1–2, только бэкенд.
5. **Инфраструктура.** Пока всё работает локально. Деплой (VPS + Docker Compose или
   Tailscale, CI) — отдельный этап.

## Игровые правила

6. **Уровни.** XP для перехода с уровня L на L+1 — `round(100 × L^1.5)`, таблицу
   генерирует сервер. Для L=10 в таблице ТЗ стоит 3163, по формуле получается 3162,
   используется формула. До 10-го уровня нужно 11 106 XP, до 20-го — 67 135 XP.
7. **Ошибочное выполнение.** Отменить выполнение можно до конца того же локального
   дня. Отмена добавляет в журнал компенсирующую запись. Уровень снижается только
   при такой отмене и только на столько уровней, сколько она пересекла. Если потом
   изменить формулу уровней, уже достигнутые уровни не понижаются.
8. **Защита от накрутки.** Сложность фиксируется при создании квеста. XP дают только
   первые 5 простых задач в день. Подзадачи — это чек-лист без XP.
9. **Обучение.** Первые 30 минут дают 15 XP, каждые следующие полные 30 минут — ещё
   10 XP. В день засчитывается не больше 240 минут. Если лимит сработал на середине
   квеста, награда уменьшается пропорционально.
10. **Характеристики.** Характеристику квеста можно указать явно. По умолчанию она
    берётся из категории: learning → intelligence, health → health и так далее.
    Квест на несколько направлений делит XP поровну на отдельные записи журнала.
    Показатель характеристики — её уровень по той же формуле.
11. **Ачивки «7/30/100 Days»** считают общее число активных дней, не дни подряд
    (фаза 3).
12. **Стрики** (фаза 3). Частота задаётся тремя способами: каждый день, по дням
    недели или N раз в неделю. Выходные и 2 «заморозки» в месяц серию не рвут.
    Множителей XP за серию нет.
13. **Циклы** (фаза 4). Активный цикл может быть только один. Пауза сдвигает дату
    окончания. За завершение даётся 200 XP × долю выполненных целей.
14. **Ежедневные квесты** — повторяющиеся шаблоны пользователя. AI не используется
    до фазы 5.
15. **Награды за ачивки** (фаза 3): Common — 25 XP, Rare — 50, Epic — 100,
    Legendary — 250.
16. **Офлайн.** Офлайн-режима нет. Повторный запрос безопасен благодаря `Idempotency-Key`.
17. **Интерфейс.** Тёмная тема «Premium Dark», языки RU и EN. Аватар — фото или инициалы.

## Технические решения и отклонения от ТЗ

- **Стек бэкенда:** Python 3.14, FastAPI, SQLAlchemy 2 (async, asyncpg), Alembic, PostgreSQL 18.
- **`event_id` детерминированный.** Это UUIDv5 от ключа события: квест, дата
  выполнения, номер выполнения, характеристика. Уникальность `event_id` в ТЗ защищала
  бы от дублей, только если повторный запрос приходит с тем же id. Детерминированный
  ключ гарантирует это.
- **`quest_completions` заменена на `quest_occurrences`.** Таблица хранит не только
  выполнения, но и пропуски и отмены по дням (по неделям для weekly). Без этого
  Adaptive Engine не сможет посчитать долю выполненного.
- **Разовые квесты.** У разового квеста одно выполнение, привязанное к дате начала
  (`anchor_date`). Поэтому «снял отметку → отметил завтра» не даёт XP второй раз.
- **Журнал XP защищён на уровне базы.** Триггер запрещает UPDATE и DELETE. DELETE
  разрешён только при удалении аккаунта, через флаг транзакции
  `lifeos.allow_ledger_delete`.
- **Поля журнала.** `reason` — машинный код, по нему клиент показывает текст на
  нужном языке. `description` — снимок названия квеста.
- **Конкурентность.** Блокировки берутся в одном порядке: квест → выполнение → профиль.
  Дневные лимиты проверяются под блокировкой профиля и поэтому точны и при
  параллельных запросах.
- **Часовой пояс.** Новый пояс начинает действовать со следующей локальной полуночи
  старого пояса.
- **Баланс хранится в таблице `game_config`.** Это награды и кривая уровней. У
  квеста остаётся награда, рассчитанная при его создании.
- **Удаление квеста мягкое** (`deleted_at`). XP, заработанный на квесте, остаётся.
- **Время.** Бизнес-логика получает текущее время через зависимость `get_now`. Тесты
  подменяют его. JWT проверяются по реальным часам.

## Что не вошло в фазы 1–2

- Достижения, стрики, привычки — фаза 3.
- Циклы и итоговые отчёты — фаза 4.
- Adaptive Engine — фаза 5.
- Автоматические условия квестов вроде «5 тренировок за неделю» — сейчас квесты
  закрываются вручную.
- Ограничение частоты попыток входа, очистка старых `Idempotency-Key`, экспорт данных.
